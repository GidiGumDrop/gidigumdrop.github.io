NL-to-ASP

Can a language model turn a natural-language combinatorial problem into a working clingo program? Each entry is a harness (how the model is run) paired with a model. The program it writes must solve the problem through Answer Set Programming and print an answer that the problem's validator accepts.

    About the benchmark

    Scoring

    • The model gets the problem text only. Its program must solve the problem with clingo and print the answer as JSON.
    • We run the saved program (120 s limit) and pass its output to the problem's validator: pass or fail.
    • Each entry is run 3 times on all 97 problems. The solve rate is the mean; the interval is a 95% bootstrap over problems.
    • Time limit per problem: ASPBench 20 min, GridPuzzles 10–25 min by size, ZebraLogic, Sudoku-Bench and LPCP 30 min.
    • Cost is the measured API cost per task (one run of one problem). Models marked * were run locally; their cost is estimated from their own token counts at OpenRouter list prices, with 71% of input tokens at the cache price (the median of the API models' bills). Granite 4.2 3B is not on OpenRouter and has no estimate.
